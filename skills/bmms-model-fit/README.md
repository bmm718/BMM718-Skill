# BMMS 模型适配体检

**调用名：`bmms-model-fit` · 版本：0.1.0**

当你说“现在模型又提升了”“又发布新模型了”“模型升级了”时，Agent 会核对具体模型的变化，检查现有 AGENTS 与 Skills 是否需要调整。准备换主力模型，或出现重复确认、做一半停住、额外搭系统时，也可以调用。

## 怎样使用

把完整 `bmms-model-fit` 目录放入当前 Agent 支持的 Skill 安装位置。按照宿主已有的安装与同步方式接入，无需另装评估平台。文字审阅由 Agent 完成；使用虚构文件题库时需要 Python 3.9 或更高版本，只用标准库。

自然触发示例，无需记住调用名：

- “现在模型又提升了。”
- “又发布新模型了，这次是【模型名】。”
- “模型升级了，看看我们现有规则还合不合适。”

默认核对模型变化并只读体检；型号或范围已有上下文就直接沿用。需要一并修改时可以说“该调整的直接优化”，或者沿用已经给出的优化授权。明确只看新闻、性能或价格时，Agent 按对应请求处理。

也可以直接指定任务：

- “用 bmms-model-fit 检查当前规则对我准备使用的模型是否合适，先只读审阅。”
- “针对最近重复确认的问题体检并优化，范围是这个项目的 AGENTS 和正在用的三个 Skills。”
- “用同一个目标模型比较修改前后规则，先跑八个基础场景，记录真实执行和未验证部分。”

只有信息会改变本次交付且无法从上下文确定时才补问。指定模型、已确认范围和此前授权直接沿用。

## 会得到什么

- 哪条规则有问题、证据在哪里、什么请求会触发，以及应保留的业务边界。
- 已授权修改的精确差异、相关验证与同步状态。
- 有真实模型执行时给行为证据；没有时交付静态结论与未验证项。

默认复杂报告为本地 HTML 和结构化证据。真实指令快照、配置、日志和结果留在用户项目或指定运行目录，不进入本 Skill。

## 八类基础场景

明确修改、只读分析、已授权续跑、短肯定、先本地后发布、已完成后收工、歧义删除、明确禁止联网。题库完全合成。脚本准备场景并核对文件状态；是否多问、提前停止、越权和伪称完成，需要独立观察者结合执行记录判断。

模型测试使用宿主已有的模型选择和隔离能力。本 Skill 不内置模型 API、账号或付费服务，不更改全局模型配置。调用不到指定模型时仍可静态审阅，但不会把其他模型的结果记作指定模型实测。

## 复查方式

你主动提到模型能力提升、新模型发布或实际执行问题时即可启动。下一次优先核对新增变化并检查相关规则，不重复已完成且仍适用的部分。这里是对话触发；后台监控需要另外明确设置。
