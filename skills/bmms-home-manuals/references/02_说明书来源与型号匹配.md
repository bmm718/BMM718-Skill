# 说明书来源与型号匹配

## 铭牌通常在哪

用户不知道型号时按下面提示让他找，不让他凭印象报：

| 类别 | 铭牌常见位置 |
|---|---|
| 冰箱 | 冷藏室内侧壁、门框内侧 |
| 洗衣机 | 机身背面、门圈内侧、顶盖下 |
| 空调 | 室内机侧面或底部、室外机侧面 |
| 热水器 | 机身侧面或底部 |
| 台灯、吊灯 | 底座底部、灯杆、电源适配器 |
| 小家电（电饭煲、空气炸锅、吸尘器） | 机身底部 |
| 路由器、网关、智能音箱 | 机身底部二维码旁 |

拿不准就让用户拍一张铭牌照片，Agent 从照片读型号，读出来念回给用户确认。

## 真源优先级

按可信度排五级。每一级都必须型号精确匹配（见下节），型号对不上就不进这一级，往下走：

1. **厂商官网托管的文件**。品牌方自己域名下的说明书 PDF 或在线说明书页。
2. **厂商原稿托管在别处**。PDF 元数据、版权页、品牌标识能看出是厂商原稿，但放在经销商站、地区站或说明书站上。来源写"官方文件托管于 <站名>"。
3. **第三方说明书站的扫描或转录版**。
4. **用户拍的纸质说明书**。放 `说明书_用户拍照/`，文件名按页码。只能回答看得清的部分，看不清的页直说。
5. **近似型号**。只有用户决定才用，`来源.md` 标"近似型号，用户决定"，每次回答都先提醒"这是 XX-123 的说明书，你的是 XX-123A"。

"厂商"指品牌方。合规声明里的制造商和品牌方不是同一家时，记在 `来源.md` 备注，不改分级。

## 怎么到达

优先级管"信谁"，到达方式管"怎么拿到"，按 Agent 能力分两条路，目标都是先拿第 1 级：

- **有浏览器能力的 Agent**：进品牌官网的支持页，按型号搜。拿到就停。没有再走下一条。
- **没有浏览器的 Agent**（实测：官网支持页多是脚本渲染，直接抓取拿到的是空壳，不要手动拼官网网址去碰）：先用搜索引擎限定品牌官方域名搜 "<型号> pdf"，有就是第 1 级；没有再放开搜 "<型号> 说明书 pdf"、"<型号> user manual pdf"、"<品牌> <产品名> 说明书"，在结果里按文件出处判第 2 级还是第 3 级。

两条路都给自己设上限，比如 12 次工具调用或 30MB，超了就停，报"没找到"并说明走到了第几级，不无限试。

每份文件进库前核对两件事：

- **型号**：全文搜清单里的型号字符串。封面、规格段、合规声明、适用型号表，任一处出现即一致。不要只看封面，很多说明书封面只印产品名，型号在规格段。多型号共用一本的，确认清单型号在它的适用型号列表里。
- **语言与地区版本**：型号对上之后看正文语言和版本标识（国际版、欧版、国行）。外文版或国际版照样入库，但要告诉用户"这是国际版，没有中文，功能可能和国行有差别；要国行版请拍纸质说明书"，并在清单和 `来源.md` 标出来。

## 型号严格匹配

- 一个字母、一个数字、一个后缀都算不同型号。XX-123 和 XX-123A 是两台机器。
- 找不到精确型号时，Agent 只能说"没找到 XX-123A，找到了 XX-123，不确定是否适用"，由用户决定要不要先用，用了在 `来源.md` 标"近似型号，用户决定"。
- 不把近似型号的说明书直接当真源回答。

## 来源.md 格式

```markdown
# 来源

型号：XX-123A
文件：说明书.pdf
来源：官方 ／ 官方文件托管于（站名） ／ 第三方（站名） ／ 用户拍照 ／ 近似型号（用户决定）
下载或拍照地址：<网址或"用户手机">
下载或拍照日期：YYYY-MM-DD
型号核对：封面 ／ 规格段 ／ 合规声明 ／ 适用型号表 含本型号 ／ 未能核对
语言与版本：中文国行 ／ 国际版无中文 ／ 其他（写明）
备注：制造商与品牌方不同、PDF 为整张拼版等
```
