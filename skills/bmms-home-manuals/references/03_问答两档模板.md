# 问答两档模板

## 先做的事

1. 确认是哪一台。家里有两台同类的，问"是厨房那台还是阳台那台"。
2. 先读这台的 `这台的坑.md`，有记录优先引用。
3. 再读说明书，找直接对应的章节。

## 档一 · 说明书写了

```
【说明书写了】<型号> 说明书 PDF 第 N 页 "<章节名>"（印刷页码不同时加：印刷页 M）：
<用说明书的意思回答，可以转成人话，不加说明书没有的步骤>
要原文的话我贴给你。
```

说明书写了但用户照做没解决，转档二，开头说明"说明书的做法你试过了没解决，下面是推测"。

## 档二 · 说明书没写

```
【说明书没写这个，下面是推测】
你的情况：<型号>，<现象，用用户的话复述一遍>。
可能的原因，按我觉得的概率排：
1. <原因一>：<为什么像>
2. <原因二>：<为什么像>
3. <原因三>：<为什么像>
先排第 1 条：<让用户做一个具体动作>，<观察什么>，<多久>。
结果告诉我，我再往下排。
```

规则：

- 一次只让用户做一件事，做完回报再给下一步。
- 排除顺序优先选用户动手最少、最能一次区分的那一步。
- 每一轮用户回报后，明说哪些可能被排除了、为什么。
- 全程不说"肯定是""一定是"，推测就是推测。
- 碰到拆机、电路、燃气，停下来引说明书安全章节，建议售后。

## 诊断前追问清单

现象说不清时按这几条问，问到够用为止，不全问：

- 什么时候出现：一开就有，还是用了多久之后
- 单独用有没有，和别的设备一起用才有
- 最近改过什么：换了位置、换了插座、换了路由器、升级了固件
- 多久一次，每次持续多久
- 重启过没有，重启后多久复发
- 指示灯、提示音、屏幕有没有异常

## 解决后

问一句："要不要把这次的真正原因和解法记进这台的坑？"用户确认才写，格式：

```markdown
## YYYY-MM-DD <现象一句话>
原因：<用户确认的原因>
解法：<用户实际做的动作>
说明书里：没写 ／ 第 N 页写了但不管用
```
